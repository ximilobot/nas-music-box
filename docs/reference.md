# 配置、排障与实现说明

[← 返回说明](../README.md)

## 界面

- 底部四个页签：曲库（全部歌曲 / 按文件夹）、歌单（我的收藏、自建歌单、文件夹歌单）、搜索、设置。
- 顶部显示连接状态和当前音箱；有问题时出现提示条。
- 播放时底部有迷你播放条，点开是全屏播放页：封面、进度、音量、播放模式、收藏、队列、定时关闭、让音箱播报一段文字。
- 搜索支持歌名 / 歌手 / 专辑 / 文件名，可以空格分开多个词（例如「周杰伦 晴天」），允许少量错字。
- 可以用浏览器的「添加到主屏幕」放个图标。注意：通过 `http://局域网IP` 访问时，浏览器不允许安装成真正的离线应用（那需要 HTTPS），添加出来的是一个快捷方式，功能不受影响。想要全屏、音量键控制，请用下面的安卓 App。

## 配置项

网页「设置」里可改的主要项目：

| 项目 | 默认 | 说明 |
| --- | --- | --- |
| 音箱拉流地址 | 自动识别 | 音箱取音频用的 NAS 地址，如 `http://192.168.1.10:8090` |
| 播放接口 | 自动 | OH2P 等型号用「音乐接口」；播不了时可以手动换另一种试 |
| 转码 | 仅列表内格式 | 也可选「全部转 mp3」或「关闭」 |
| 需要转换的格式 | ape, wma, ogg | 逗号分隔。flac / m4a / wav 默认直接给音箱，播不了就加进来 |
| 转码码率 / 缓存上限 | 320k / 2048 MB | 转过的歌缓存在 `data/cache`，超出上限自动删最久没用的 |
| 语音口令开关、读取间隔 | 开，1.5 秒；空闲 5 秒 | |
| 播放状态查询间隔 | 3 秒 | 播放时多久问一次音箱「播到哪了」 |
| 会话检测间隔 / 提前续期周期 | 10 分钟 / 24 小时 | 见「稳定性」第 3 条 |
| 音量步进 | 5 | 音量加 / 减一档的幅度 |
| 播报方式 | 自动 | 文字播报用哪种接口，播不出来时可换 |
| 访问密码 | 未设置 | 设置后打开网页要先输密码 |
| 外观 | 跟随系统 | 浅色 / 深色 |

`docker-compose.yml` 里的环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `NASBOX_PORT` | 8090 | 监听端口 |
| `NASBOX_BASE_URL` | 空 | 音箱拉流地址；网页设置里填了的话以网页为准 |
| `TZ` | Asia/Shanghai | 时区（影响日志时间） |
| `NASBOX_MUSIC_DIR` / `NASBOX_DATA_DIR` | /music、/data | 容器内路径，一般不用改 |

忘了访问密码：停止容器，删掉 `data/settings.json` 里的 `password_hash` 那一行的值（改成 `""`），再启动。

## 排障

先看网页顶部的状态和设置页的「最近错误」。设置页最下面可以查看最近日志、下载脱敏日志包。

| 现象 | 处理 |
| --- | --- |
| 点了歌，界面显示在播，音箱没声音 | 多半是音箱拉流地址不对。设置页看当前地址是不是 NAS 的局域网 IP 和端口；bridge 网络必须手填。再确认群晖防火墙放行了 8090。日志里有「拉流 GET」字样说明音箱来取过文件 |
| 日志里有「拉流」，但还是没声音或马上跳下一首 | 音箱不认这个格式。把该格式加到「需要转换的格式」；还不行就把转码改成「全部转 mp3」 |
| mp3 也播不了 | 把「播放接口」从自动换成另一种试 |
| 状态显示「网络异常」 | NAS 暂时连不上小米服务器，程序会自己重试，登录状态不受影响。长期如此检查 NAS 的网络和 DNS |
| 状态显示「需要重新扫码」 | 小米那边确认登录失效了（改过密码、在米家里移除了登录设备、太久没用等），重新扫码即可。歌单、收藏、设置不受影响 |
| 一首播完不自动下一首 / 提前切歌 | 下载日志包。这是最依赖真实音箱行为的部分，见说明里的「已知局限」 |
| 语音口令没反应 | 设置页「语音口令」里看最近一次识别到的话和错误；确认当前选中的音箱就是你说话的那台（只监听选中的那台）；用「口令测试」确认这句话能被解析 |
| 音箱关机后页面提示「音箱没有响应」 | 正常。程序已停止播放和重试；音箱开机后过一会儿状态会变回在线，点播放从当前这首继续 |
| 说了口令，小爱先自己答了半句 | 正常，读取对话记录有延迟，程序发现后才能打断 |
| 曲库是空的 | 检查 compose 里曲库路径；用普通用户运行时检查读取权限；点「重新扫描」 |
| 新加的歌没出现 | 点「重新扫描」。程序不会自动监视文件夹 |
| 歌名是乱码 | 文件标签编码问题（老 mp3 常见的 GBK 标签）。用标签工具转成 UTF-8 后重新扫描 |
| 容器起不来 | 看 Container Manager 里的容器日志；常见是 8090 端口被占用（改 `NASBOX_PORT`）或 `data` 文件夹不可写 |

## 稳定性：为了不掉线做了什么

写这个项目的直接原因是同类方案用久了经常掉线。逐条说明做法：

1. **登录凭据不会因为一次失败就被清空。** 常见的掉线原因是：任何一次登录异常就把凭据清空、删掉凭据文件，而且每次登录换一个随机的浏览器标识。本程序：设备标识和浏览器标识第一次生成后固定保存；凭据文件用「写临时文件再改名」的方式保存，断电也不会写坏，权限仅所有者可读写；网络错误（超时、连不上、服务器 5xx）只做退避重试，凭据原样不动；只有小米明确回答「登录已失效」并且**间隔几秒再确认一次**仍然如此，才把状态标成「需要重新扫码」，这时旧凭据文件还会留一份备份（`credentials.json.bak-needqr-日期`）。
2. **扫码登录，不保存账号密码。** 网页显示二维码，米家 App 扫码确认。
3. **连接健康度看得见。** 后台每 10 分钟检查一次会话，每 24 小时主动续期一次，不等到失效才处理。网页顶部始终显示状态：正常 / 续期中 / 网络异常 / 需要重新扫码 / 未登录；设置页显示最近一次成功的时间和最近一次错误。会话临时失效时自动用长期凭据静默续期，多个请求同时遇到失效也只续期一次，连续失败按 2 秒、4 秒……最长 5 分钟逐步拉长间隔。
4. **切歌不靠盲目定时。** 只按文件时长设定时器、时间到了就切，容易切早或切晚。本程序每 3 秒向音箱查询播放状态，音箱肯上报进度就按真实进度判断是否播完；OH2P 不上报进度，就以「音箱回头重新拉取同一首」作为播完信号，文件时长的定时器兜底。下发播放失败会重试，重试期间界面显示「重试中」，队列不会断；音箱开始播放前不会被重复下发；你在音箱上手动暂停能被识别出来，不会被当成「播完了」而切歌；歌曲文件没了或播不了会自动跳到下一首，连续多首都失败才停下来。所有云端请求都有超时。
5. **语音口令**：见 [语音点歌和口令](voice.md)。可关闭，间隔可调，空闲时自动放慢。
6. **日志不含敏感信息。** token、cookie、长期凭据一律不写日志（写入前统一过滤一遍）。设置页可以下载脱敏后的日志包，里面的设备 ID 也做了遮挡，可以放心发给别人帮忙看。

## 实测情况

**在 OH2P + x86 群晖（Container Manager 源码构建）上实际跑通的：** 扫码登录、换取会话凭据、flac 直接播放、网页点播、一首播完自动下一首、带关键词的语音口令、让小爱播别的内容时让出控制、音箱关机识别。

**只在「模拟的小米云端」上测过、没有实机确认的：**

1. 长期凭据失效时小米服务器的真实回应（关系到「需要重新扫码」判断得准不准）；连续运行很多天的稳定性；会话凭据的实际有效期。
2. 被对话打断后自动重放、每次播放后把音箱循环模式设回列表循环。这几项是较新的改动。
3. 拖动进度、文字播报、边转码边发送的音频流、mp3 之外各种格式在其他型号上的表现。
4. 预构建镜像在各种环境下的拉取和运行。
5. 安卓 App 在各种手机上的表现。

自动化测试共 39 项服务端测试 + 46 项界面流程检查，全部是对模拟云端跑的，通过不代表在真实音箱上没问题。

## 安卓 App 与网页的约定

| 约定 | 说明 |
| --- | --- |
| `GET /api/status` | 免登录，始终返回 200 和 JSON 对象。设了访问密码且未登录时只有 `app`、`name`、`version`、`need_login`、`authed`、`auth`（连接健康状态：`state` 和中文 `label`）几项，不含设备、账号等信息 |
| 首页 | 始终返回 200；访问密码是页面内的登录框，不是跳转或 401 |
| `window.NasBoxApp` | 存在即表示运行在 App 里 |
| `NasBoxApp.openSettings()` | 打开原生的服务器设置页；网页的「App 设置 / 切换服务器」调用它 |
| `NasBoxApp.setBarColor(css颜色)` | 网页在启动和切换深浅色后调用，同步状态栏 / 导航栏颜色；页面同时带 `<meta name="theme-color">` |
| `NasBoxApp.getVersion()` | 返回 App 版本号，网页显示在「App 设置」入口上 |
| `NasBoxApp.reload()` / `NasBoxApp.showMenu()` | 刷新页面 / 弹出原生菜单；网页目前没有用到 |
| `window.__nasbox_volume(delta)` | 网页定义；App 在按音量键时调用，`delta` 为 `+1` 或 `-1`，表示音箱音量加 / 减一档 |

## 开发与测试

```bash
cd server
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest tests.test_all    # 39 项，全部对模拟云端；需要本机有 ffmpeg（自动生成 8 首带标签的测试音频）
```

`tests/mock_cloud.py` 是模拟的小米云端（登录续期、扫码、设备列表、音箱控制、对话记录）。`tests/ui_smoke.js` 在 jsdom 里加载真实网页、连真实服务进程跑一遍界面流程（需要 `npm i jsdom`，文件头有用法）。

用环境变量 `NASBOX_ACCOUNT_BASE`、`NASBOX_MINA_BASE`、`NASBOX_PROFILE_BASE`、`NASBOX_MIIO_BASE` 可以把服务端指向模拟云端，仅测试用。
