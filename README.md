# NAS 音乐盒

让小爱音箱播放 NAS 上的本地歌曲。服务端跑在 NAS 的 Docker 里，用手机浏览器或配套的安卓 App 点歌，也可以直接对音箱说话点歌。

> **先看这几句**
>
> - 这是一个**自用项目，代码全部由 AI 编写**，作者本人只负责提需求和在自己家里实测。没有人工逐行审过代码。
> - **只在一台 Xiaomi 智能音箱 Pro（型号 OH2P）+ x86 群晖上实测过。** 其他型号的小爱音箱没有条件测试，能不能用不知道，出了问题我也没法帮你调。
> - 音箱没有刷机，播放指令要经过小米云端的**非公开接口**下发。小米改接口就会失效；用它登录你的小米账号有什么后果由你自己承担。
> - 不保证维护，不保证回复 issue。觉得有用可以自己拿去改（MIT 许可）。

## 主要功能

- **只做本地曲库**：扫描 NAS 上的音乐文件夹（读标签、封面），不联网搜歌、不下载、没有插件、不上报任何统计。曲库只读挂载，程序不会改动你的歌曲文件。
- **网页控制**：手机优先的界面，曲库 / 文件夹 / 歌单 / 收藏 / 搜索 / 播放队列 / 播放模式 / 音量 / 定时关闭 / 文字播报。
- **语音点歌**：对音箱说「播放周杰伦的歌」「我想听晴天」，曲库里有就由 NAS 播，没有才交给小爱自己的曲库。
- **扫码登录**：米家 App 扫码，不保存账号密码。登录凭据不会因为一次网络抖动被清掉（见「稳定性」一节）。
- **格式**：mp3 / flac / m4a / wav 直接给音箱；ape / wma / ogg 等用 ffmpeg 转成 mp3 再播，转码结果有缓存。
- **音箱关机能识别**：音箱没响应时停止播放和重试，保留队列，低频探测，恢复后不会自己出声。
- **安卓 App（可选）**：套在网页外面的原生壳，约 46 KB，手机音量键直接调音箱音量。

## 部署到群晖

以下按 x86 群晖（DSM）写，这是唯一实测过的环境。其他能跑 Docker 的 x86 NAS 或 Linux 主机步骤类似。

### 1. 准备文件夹

1. 用 File Station 在 `docker` 共享文件夹里新建 `nas-music-box`，把本仓库下载下来（GitHub 页面 Code → Download ZIP），把里面的 `docker-compose.yml` 和整个 `server` 文件夹上传进去。上传后应当是：
   - `/volume1/docker/nas-music-box/docker-compose.yml`
   - `/volume1/docker/nas-music-box/server/Dockerfile` 等
2. 在 `/volume1/docker/nas-music-box/` 下再新建一个空文件夹 `data`（存配置、数据库、登录凭据、转码缓存）。
3. 歌曲默认按 `/volume1/music` 读取。你的歌不在这里的话，改 `docker-compose.yml` 里 `volumes` 的第一行冒号左边的路径。

### 2. 启动

**DSM 7.2 及以上（Container Manager）**

1. 打开 Container Manager →「项目」→「新增」。
2. 项目名称填 `nas-music-box`，路径选 `/volume1/docker/nas-music-box`，来源选「使用现有的 docker-compose.yml」。
3. 一路下一步（「网页门户」那步不用设置），勾选「项目创建后立即启动」，完成。
4. 第一次会在 NAS 上构建镜像（下载 Python 基础镜像、安装 ffmpeg），需要几分钟。构建日志里卡住或报错，多半是网络问题，看下面「国内网络」。

**旧版 DSM（Docker 套件，没有「项目」功能）**

在控制面板 → 终端机和 SNMP 里启用 SSH，然后：

```bash
ssh 你的管理员账号@NAS的IP
cd /volume1/docker/nas-music-box
sudo docker-compose up -d --build      # 新版本的写法是 sudo docker compose up -d --build
```

启动后用手机或电脑浏览器打开 `http://NAS的IP:8090`。

### 3. 网络方式：host 还是端口映射

音箱是自己直接向 NAS 取音频文件的，所以程序必须知道「NAS 在局域网里的地址」，这个地址叫**音箱拉流地址**。

- **host 网络（默认，推荐）**：容器直接用 NAS 的网络，程序能自动认出 NAS 的局域网 IP，一般不用手填。代价是端口 8090 直接占用 NAS 的端口；被占用就改 `docker-compose.yml` 里的 `NASBOX_PORT`。
- **端口映射（bridge）**：把 `network_mode: host` 注释掉，启用 `ports`。这时容器里看到的是 Docker 内部 IP，自动识别不准，**必须**在网页「设置 → 音箱拉流地址」里手填 `http://NAS的局域网IP:8090`（或在 compose 里设 `NASBOX_BASE_URL`）。

两种方式下，如果 NAS 有多块网卡或开着 VPN，自动识别都可能选错网卡，也请手填。设置页会显示当前实际使用的地址。另外：用浏览器通过局域网 IP 打开网页时，程序会记下这个地址当作备选。

给 NAS 在路由器里绑定固定 IP，否则 IP 一变，手填的地址就失效了。

### 4. 群晖防火墙

控制面板 → 安全性 → 防火墙。如果启用了防火墙，新增一条规则放行 TCP 8090，来源 IP 限定为你的局域网网段（例如 192.168.1.0/255.255.255.0）。没启用防火墙就不用管。

**不要**在路由器上把 8090 映射到公网，也不要给它做外网反向代理：这个服务能控制你家音箱，并保存着小米账号的登录凭据。在外面想用，请走群晖自带的 VPN Server 或 Tailscale 之类的方式回到家里内网。

### 5. 共享文件夹权限

- 曲库是**只读挂载**（`:ro`），程序不会也不能改动、删除你的歌曲文件。
- 容器默认以 root 运行，对群晖共享文件夹开箱即用，不需要额外设置权限。
- 想用普通用户运行：SSH 里执行 `id 你的用户名` 查到 uid 和 gid（群晖第一个自建用户通常是 1026，users 组是 100），把 `docker-compose.yml` 末尾的 `user: "1026:100"` 取消注释。前提是这个用户对曲库文件夹有读取权限、对 `data` 文件夹有读写权限（File Station 右键 → 属性 → 权限）。
- `data` 文件夹里的 `credentials.json` 是小米账号的登录凭据，程序把它的权限设成仅所有者可读写。不要把 `data` 文件夹共享给别人，也不要发到网上。

### 6. 国内网络

构建镜像要从 Docker Hub 拉基础镜像、从 Debian 源装 ffmpeg、从 PyPI 装三个 Python 包，国内可能很慢或失败。`docker-compose.yml` 里留了三个参数：

```yaml
      args:
        BASE_IMAGE: python:3.12-slim       # 改成镜像站地址
        APT_MIRROR: ""                     # 例如 mirrors.ustc.edu.cn
        PIP_INDEX_URL: ""                  # 例如 https://pypi.tuna.tsinghua.edu.cn/simple
```

- `APT_MIRROR`、`PIP_INDEX_URL`：填上面注释里的例子即可（中科大、清华的公开镜像）。
- `BASE_IMAGE`：Docker Hub 的镜像站变动很频繁，没有一个能保证长期可用的地址。可以先在 Container Manager →「注册表」→「设置」里给 Docker Hub 配一个你正在用的镜像加速地址；或者把 `BASE_IMAGE` 写成 `镜像站域名/library/python:3.12-slim` 的形式；NAS 能走代理的话最省事。
- 改完后在项目里点「操作 → 构建」重新构建。

### 7. 升级与备份

- 升级：用新的 `server` 文件夹覆盖旧的，在项目里「操作 → 构建」。`data` 文件夹不要动，登录状态、歌单、收藏都在里面。
- 备份：备份 `data` 文件夹即可。

### 8. 用现成镜像（可选）

不想在 NAS 上构建的话，可以直接拉镜像。仓库里的 GitHub Actions 会在 `server/` 有改动时自动构建 amd64 镜像，推送到 `ghcr.io/ximilobot/nas-music-box`（标签 `latest` 和版本号）。

1. 只需要上传 `docker-compose.image.yml`，改名为 `docker-compose.yml`，放到 `/volume1/docker/nas-music-box/`，同样新建 `data` 文件夹。
2. 在 Container Manager 里按上面第 2 步新建项目。
3. 升级：项目里「操作 → 清除」后重新「构建 / 启动」，或 SSH 里 `sudo docker compose pull && sudo docker compose up -d`。

注意：国内网络拉 `ghcr.io` 可能很慢或失败，拉不动就用上面的源码构建方式。镜像方式作者自己没有用过，实测的是源码构建。

## 第一次使用

1. 浏览器打开 `http://NAS的IP:8090`，没登录时会直接进入设置页。
2. 点「扫码登录」，用**米家 App** 扫屏幕上的二维码并确认。程序不保存账号密码。
   - 手机上只有一台设备时没法扫自己的屏幕：换电脑或另一台手机打开网页来显示二维码。
3. 登录后「音箱」里会列出账号下的小爱音箱，选中要用的那台。
4. 到「曲库」确认歌曲已扫描出来（启动时自动扫描一次；之后加了新歌点「重新扫描」，只处理有变化的文件）。
5. 点一首歌试播。建议按这个顺序验证：mp3 能不能响 → 一首播完会不会自动下一首 → flac 等其它格式能不能响 → 对音箱说「播放歌曲 某某」。
   - 点了没声音：先看设置页的「音箱拉流地址」是不是 NAS 的局域网地址。
   - 某种格式播不了：在「设置 → 播放 → 需要转换的格式」里加上它（例如 `flac`），程序会用 ffmpeg 转成 mp3 再给音箱。（OH2P 实测 flac 可以直接播。）

## 界面

- 底部四个页签：曲库（全部歌曲 / 按文件夹）、歌单（我的收藏、自建歌单、文件夹歌单）、搜索、设置。
- 顶部显示连接状态和当前音箱；有问题时出现提示条。
- 播放时底部有迷你播放条，点开是全屏播放页：封面、进度、音量、播放模式、收藏、队列、定时关闭、让音箱播报一段文字。
- 搜索支持歌名 / 歌手 / 专辑 / 文件名，可以空格分开多个词（例如「周杰伦 晴天」），允许少量错字。
- 可以用浏览器的「添加到主屏幕」放个图标。注意：通过 `http://局域网IP` 访问时，浏览器不允许安装成真正的离线应用（那需要 HTTPS），添加出来的是一个快捷方式，功能不受影响。想要全屏、音量键控制，请用下面的安卓 App。

## 语音点歌和口令

对音箱说「小爱同学」之后说下面的话。程序每隔一两秒读取一次小爱的对话记录，听到要处理的话就先打断小爱自己的回答，再执行。所以小爱通常会先答半句、甚至先响一下它自己的内容，这个延迟避免不了。

**直接点歌（不用说关键词）**

说「播放 / 我想听 / 来一首 + 名字」，程序先查 NAS 曲库：

| 你说的是 | 结果 |
| --- | --- |
| 歌手，如「播放周杰伦的歌」 | 这位歌手在曲库里的全部歌曲 |
| 专辑名 | 整张专辑，按音轨顺序 |
| 歌名，或「歌手的歌名」 | 这首在前，后面接同文件夹的其他歌 |
| 自建歌单名或文件夹名 | 这个歌单 / 文件夹 |
| 曲库里没有的东西 | 交给小爱自己播，程序让出控制、不再发指令 |

这种说法只认**完全一致**的名字，免得误抢小爱自己的内容。歌手按歌曲文件里的「歌手」标签匹配，标签没填的歌进不了歌手队列。设置里有开关「曲库里有就由 NAS 播」。

**带关键词的口令（模糊匹配）**

| 口令 | 作用 |
| --- | --- |
| 播放歌曲 | 接着上次的队列播；没有队列就播放全部歌曲 |
| 播放歌曲 + 名字 | 歌手 / 专辑 / 歌名，允许不完全一致，如「播放歌曲周杰伦的晴天」 |
| 播放歌单 + 名称 | 自建歌单或文件夹名，如「播放歌单粤语」；「播放歌单收藏」播我的收藏 |
| 上一首 / 下一首 | |
| 暂停 / 继续 | 「继续」在 OH2P 上是从头重放当前这首，见「已知局限」 |
| 停止 | |
| 单曲循环 / 全部循环 / 随机播放 | |
| 加入收藏 / 取消收藏 | 针对正在播的歌 |

**播放中跟小爱说别的话**

- 调音量、问天气这类对话会把歌打断。程序等小爱答完，音箱没有自己恢复，就从头重放当前这首。设置里有开关「被对话打断后自动重放」。
- 说「别放了」「关掉音乐」这类话，按暂停处理，不会自动重放。
- 让小爱播曲库里没有的内容，程序让出控制；之后在网页点播放，是重新播放 NAS 的歌。

其他说明：

- 口令关键词可在「设置 → 语音口令」里改，多个说法用逗号隔开；设置页里有个「口令测试」输入框，只解析不执行。
- 「上一首 / 下一首 / 暂停 / 继续 / 停止 / 收藏」只在本程序正在播放或暂停时才生效，避免抢走小爱自己的功能。
- 长时间（默认 30 分钟）没有播放也没有口令时，读取间隔自动放慢到 5 秒，这时第一句话的反应会慢一点。
- 匹配是按文字来的，小爱把名字听成了同音的别的字就找不到。
- 不想让程序读取对话记录，可以在设置里关掉语音口令，只用网页 / App 控制。

## 配置项

网页「设置」里可改的主要项目：

| 项目 | 默认 | 说明 |
| --- | --- | --- |
| 音箱拉流地址 | 自动识别 | 音箱取音频用的 NAS 地址，如 `http://192.168.1.10:8090` |
| 播放接口 | 自动 | OH2P 等型号用「音乐接口」；播不了时可以手动换另一种试 |
| 转码 | 仅列表内格式 | 也可选「全部转 mp3」或「关闭」 |
| 需要转换的格式 | ape, wma, ogg | 逗号分隔。flac / m4a / wav 默认直接给音箱，播不了就加进来 |
| 转码码率 / 缓存上限 | 320k / 2048 MB | 转过的歌缓存在 `data/cache`，超出上限自动删最久没用的 |
| 语音口令开关、读取间隔 | 开，1.5 秒；空闲 5 秒 | |
| 播放状态查询间隔 | 3 秒 | 播放时多久问一次音箱「播到哪了」 |
| 会话检测间隔 / 提前续期周期 | 10 分钟 / 24 小时 | 见下面「稳定性」第 3 条 |
| 音量步进 | 5 | 音量加 / 减一档的幅度 |
| 播报方式 | 自动 | 文字播报用哪种接口，播不出来时可换 |
| 访问密码 | 未设置 | 设置后打开网页要先输密码 |
| 外观 | 跟随系统 | 浅色 / 深色 |

`docker-compose.yml` 里的环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `NASBOX_PORT` | 8090 | 监听端口 |
| `NASBOX_BASE_URL` | 空 | 音箱拉流地址；网页设置里填了的话以网页为准 |
| `TZ` | Asia/Shanghai | 时区（影响日志时间） |
| `NASBOX_MUSIC_DIR` / `NASBOX_DATA_DIR` | /music、/data | 容器内路径，一般不用改 |

忘了访问密码：停止容器，删掉 `data/settings.json` 里的 `password_hash` 那一行的值（改成 `""`），再启动。

## 稳定性：为了不掉线做了什么

写这个项目的直接原因是同类方案用久了经常掉线。逐条说明做法：

1. **登录凭据不会因为一次失败就被清空。** 常见的掉线原因是：任何一次登录异常就把凭据清空、删掉凭据文件，而且每次登录换一个随机的浏览器标识。本程序：设备标识和浏览器标识第一次生成后固定保存；凭据文件用「写临时文件再改名」的方式保存，断电也不会写坏，权限仅所有者可读写；网络错误（超时、连不上、服务器 5xx）只做退避重试，凭据原样不动；只有小米明确回答「登录已失效」并且**间隔几秒再确认一次**仍然如此，才把状态标成「需要重新扫码」，这时旧凭据文件还会留一份备份（`credentials.json.bak-needqr-日期`）。
2. **扫码登录，不保存账号密码。** 网页显示二维码，米家 App 扫码确认。
3. **连接健康度看得见。** 后台每 10 分钟检查一次会话，每 24 小时主动续期一次，不等到失效才处理。网页顶部始终显示状态：正常 / 续期中 / 网络异常 / 需要重新扫码 / 未登录；设置页显示最近一次成功的时间和最近一次错误。会话临时失效时自动用长期凭据静默续期，多个请求同时遇到失效也只续期一次，连续失败按 2 秒、4 秒……最长 5 分钟逐步拉长间隔。
4. **切歌不靠盲目定时。** 只按文件时长设定时器、时间到了就切，容易切早或切晚。本程序每 3 秒向音箱查询播放状态，音箱肯上报进度就按真实进度判断是否播完；OH2P 不上报进度，就以「音箱回头重新拉取同一首」作为播完信号，文件时长的定时器兜底。下发播放失败会重试，重试期间界面显示「重试中」，队列不会断；音箱开始播放前不会被重复下发；你在音箱上手动暂停能被识别出来，不会被当成「播完了」而切歌；歌曲文件没了或播不了会自动跳到下一首，连续多首都失败才停下来。所有云端请求都有超时。
5. **语音口令**：见上面「语音口令」一节。可关闭，间隔可调，空闲时自动放慢。
6. **日志不含敏感信息。** token、cookie、长期凭据一律不写日志（写入前统一过滤一遍）。设置页可以下载脱敏后的日志包，里面的设备 ID 也做了遮挡，可以放心发给别人帮忙看。

## 安卓 App

安卓 App 是套在网页外面的原生壳，源码在 `android/`，详细说明和构建方法见 `android/README.md`。仓库里不放 APK 文件；本仓库的 Releases 页面如果有，就从那里下载，没有就按说明自己构建。App 只在构建环境里编译、签名通过，实机使用反馈很少。

- 安装后第一次打开，填 `http://NAS的IP:8090`，点「测试并保存」。App 通过请求 `/api/status` 确认对面是 NAS 音乐盒。
- 在 App 里按手机音量键，调的是音箱音量（每按一下一档），不是手机音量。
- 网页「设置」页最上面有「App 设置 / 切换服务器」入口（只在 App 里显示）；设了访问密码时，登录框下面也有同样的入口。
- 切换深浅色时，状态栏颜色跟着变。

网页和 App 之间的约定（改代码时参考）：

| 约定 | 说明 |
| --- | --- |
| `GET /api/status` | 免登录，始终返回 200 和 JSON 对象。设了访问密码且未登录时只有 `app`、`name`、`version`、`need_login`、`authed`、`auth`（连接健康状态：`state` 和中文 `label`）几项，不含设备、账号等信息 |
| 首页 | 始终返回 200；访问密码是页面内的登录框，不是跳转或 401 |
| `window.NasBoxApp` | 存在即表示运行在 App 里 |
| `NasBoxApp.openSettings()` | 打开原生的服务器设置页；网页的「App 设置 / 切换服务器」调用它 |
| `NasBoxApp.setBarColor(css颜色)` | 网页在启动和切换深浅色后调用，同步状态栏 / 导航栏颜色；页面同时带 `<meta name="theme-color">` |
| `NasBoxApp.getVersion()` | 返回 App 版本号，网页显示在「App 设置」入口上 |
| `NasBoxApp.reload()` / `NasBoxApp.showMenu()` | 刷新页面 / 弹出原生菜单；网页目前没有用到 |
| `window.__nasbox_volume(delta)` | 网页定义；App 在按音量键时调用，`delta` 为 `+1` 或 `-1`，表示音箱音量加 / 减一档 |

## 排障

先看网页顶部的状态和设置页的「最近错误」。设置页最下面可以查看最近日志、下载脱敏日志包。

| 现象 | 处理 |
| --- | --- |
| 点了歌，界面显示在播，音箱没声音 | 多半是音箱拉流地址不对。设置页看当前地址是不是 NAS 的局域网 IP 和端口；bridge 网络必须手填。再确认群晖防火墙放行了 8090。日志里有「拉流 GET」字样说明音箱来取过文件 |
| 日志里有「拉流」，但还是没声音或马上跳下一首 | 音箱不认这个格式。把该格式加到「需要转换的格式」；还不行就把转码改成「全部转 mp3」 |
| mp3 也播不了 | 把「播放接口」从自动换成另一种试 |
| 状态显示「网络异常」 | NAS 暂时连不上小米服务器，程序会自己重试，登录状态不受影响。长期如此检查 NAS 的网络和 DNS |
| 状态显示「需要重新扫码」 | 小米那边确认登录失效了（改过密码、在米家里移除了登录设备、太久没用等），重新扫码即可。歌单、收藏、设置不受影响 |
| 一首播完不自动下一首 / 提前切歌 | 下载日志包。这是最依赖真实音箱行为的部分，见「已知局限」 |
| 语音口令没反应 | 设置页「语音口令」里看最近一次识别到的话和错误；确认当前选中的音箱就是你说话的那台（只监听选中的那台）；用「口令测试」确认这句话能被解析 |
| 音箱关机后页面提示「音箱没有响应」 | 正常。程序已停止播放和重试；音箱开机后过一会儿状态会变回在线，点播放从当前这首继续 |
| 说了口令，小爱先自己答了半句 | 正常，读取对话记录有延迟，程序发现后才能打断 |
| 曲库是空的 | 检查 compose 里曲库路径；用普通用户运行时检查读取权限；点「重新扫描」 |
| 新加的歌没出现 | 点「重新扫描」。程序不会自动监视文件夹 |
| 歌名是乱码 | 文件标签编码问题（老 mp3 常见的 GBK 标签）。用标签工具转成 UTF-8 后重新扫描 |
| 容器起不来 | 看 Container Manager 里的容器日志；常见是 8090 端口被占用（改 `NASBOX_PORT`）或 `data` 文件夹不可写 |

## 实测情况

**在 OH2P + x86 群晖（Container Manager 源码构建）上实际跑通的：** 扫码登录、换取会话凭据、flac 直接播放、网页点播、一首播完自动下一首、带关键词的语音口令、让小爱播别的内容时让出控制、音箱关机识别。

**只在「模拟的小米云端」上测过、没有实机确认的：**

1. 长期凭据失效时小米服务器的真实回应（关系到「需要重新扫码」判断得准不准）；连续运行很多天的稳定性；会话凭据的实际有效期。
2. 不说关键词的直接点歌、被对话打断后自动重放、每次播放后把音箱循环模式设回列表循环。这几项是较新的改动。
3. 拖动进度、文字播报、边转码边发送的音频流、mp3 之外各种格式在其他型号上的表现。
4. 预构建镜像（ghcr.io）的拉取和运行。
5. 安卓 App 在各种手机上的表现。

自动化测试共 39 项服务端测试 + 46 项界面流程检查，全部是对模拟云端跑的，通过不代表在真实音箱上没问题。

## 已知局限

**型号**

- 只支持、只测试过 Xiaomi 智能音箱 Pro（OH2P）。其他型号的播放接口、状态上报都可能不一样，作者没有设备，无法测试也无法适配。

**OH2P 这台音箱本身的限制（程序只能绕着走）**

- 没有 DLNA，不刷机就只能经小米云端控制。**NAS 断网或小米云端出问题时无法控制音箱。**
- 不上报播放进度和当前曲目，只报「在播 / 没在播」、音量、循环类型。网页上的进度条是程序按时间自己算的。
- 不支持断点续播。暂停后点继续、被打断后恢复，都是**从头重放当前这首**。
- 一首歌播完，音箱会自己把同一首从头再拉一遍，程序把这个动作当作「播完了」的信号来切歌，切歌时可能听到约 1 秒的开头。
- 分辨不了音箱在播的是 NAS 的歌还是小爱自己的内容，只能靠你说的那句话来猜。说法特别的时候可能猜错。
- 被对话打断后等多久再重放是估算的（按小爱回答的字数），可能偏早或偏晚。

**设计上不做的**

- 不联网搜歌、不下载、没有歌词、没有多人账号。
- 语音只监听当前选中的那一台音箱；按文字匹配，没有拼音容错。
- 新加的歌要手动点「重新扫描」。
- 没有账号密码登录，只能扫码。
- 不要把端口映射到公网（见「群晖防火墙」一节）。

**依赖**

- 依赖小米云端的非公开接口，接口变了就会失效，需要改代码。
